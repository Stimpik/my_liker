# my-liker

Локальный помощник для обработки уведомлений Stepik. Он использует отдельный
профиль Chrome и API, которое вызывает веб-интерфейс Stepik.

## Что обрабатывается

- Лайк обычного комментария: уведомление помечается прочитанным.
- Ответ или комментарий: остаётся непрочитанным.
- Лайк решения: скрипт ищет решение автора на этом же шаге, проверяет чёрный
  список и текущее состояние голоса. После успешного лайка либо завершённой
  проверки уведомление помечается прочитанным.
- Реклама, скидки, открытие модулей и неизвестные события: игнорируются.
- Дополнительные авторы: при включённой функции проверяются на тех шагах,
  которые встретились в уведомлениях о лайках решений.

## Установка

Проект использует Python 3.13 и Poetry.

```powershell
poetry install
```

Playwright запускает установленный Google Chrome, поэтому отдельная загрузка
Chromium не нужна.

## Первый вход

```powershell
poetry run my-liker login
```

Откроется отдельный Chrome-профиль. Войдите в Stepik вручную, откройте
уведомления и вернитесь в терминал. Пароль скрипт не получает.

## Безопасный запуск

Прочитать и классифицировать все страницы непрочитанных уведомлений:

```powershell
poetry run my-liker scan
```

`scan` одновременно строит план и сохраняет его в `data/plan.json`. План
действителен 15 минут.

Показать план действий без изменения Stepik:

```powershell
poetry run my-liker apply
```

Если `scan` выполнялся менее 15 минут назад, команда мгновенно показывает
сохранённый план без повторного обхода Stepik.

Выполнить показанный план:

```powershell
poetry run my-liker apply --yes
```

Каждый запуск выполняет следующую порцию размером `max_actions_per_run`.
Оставшаяся часть полного плана сохраняется для следующего `apply --yes`;
повторный `scan` нужен только после завершения или устаревания плана.

Команда выполняет тот же сохранённый план. Если кэш устарел, выполнение
отменяется и требуется повторный `scan` или предпросмотр `apply`.

За один запуск выполняется не больше `max_actions_per_run` логических действий.
При ответном лайке сначала ставится лайк и лишь затем уведомление помечается
прочитанным. Ошибка прерывает выполнение и сохраняет уведомление для повтора.

## Настройки авторов

Скопируйте `config.example.toml` в `config.toml` и укажите числовые ID Stepik:

```toml
[limits]
max_actions_per_run = 5

[features]
preferred_authors_enabled = true
blacklist_enabled = true

[authors]
preferred = [123456]
blacklist = [987654]
```

Чёрный список имеет приоритет, если один ID попал в оба списка.

## Статистика

```powershell
poetry run my-liker stats
poetry run my-liker stats --export data/stats.json
```

Входящие лайки учитываются по уникальному ID уведомления. Исходящие лайки
учитываются, когда их успешно поставил скрипт. Ранее поставленные вручную лайки
не восстанавливаются задним числом.

Локальные сессии, конфигурация и база данных исключены из Git.

## Ограничения

Скрипт выполняет запросы последовательно, делает паузу между страницами и
повторяет только безопасные GET-запросы при `429` и временных ошибках сервера.
Записывающие PUT-запросы автоматически не повторяются.

Решения одного задания загружаются один раз за сканирование и затем ищутся в
локальном кэше, даже если уведомлений или дополнительных авторов много.
